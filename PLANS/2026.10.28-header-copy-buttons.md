# Copy Buttons for the Session Name and the Paths in the Conversation Header

**Status:** decisions D1 to D3 made by the maintainer on 2026-10-28. Nothing is built yet.

## Why

You often need a session's name or its project path somewhere else: in a terminal, in a note, or in a message to a colleague. In the Conversation Pane header you can copy the session UUID and the file path with one click. The session name and the project path have no copy button, so you must select the text by hand, and a long path is easy to select only in part.

## The Header Today

`frontend/src/components/conversation/ConversationHeader.tsx` shows these values:

| Value | When it shows | Where | Copy button today |
|---|---|---|---|
| Session name | Always ("Untitled" when there is no name) | The `<h1>` title | No |
| Session UUID | Always | The **Details** block | Yes |
| File path (the session's file on disk, for example under `~/.claude/projects`) | When the API gives one | **Details** | Yes |
| Project path | Claude Code sessions | **Details**, after a folder icon | No |
| Git branch | Claude Code sessions with a branch | **Details**, after a branch icon | No |
| Sandbox path | Cowork sessions | **Details**, after "Sandbox path:" | No |

The two copy buttons that exist work the same way:
- The button is the copy icon followed by the value, in a monospace font.
- After a successful copy, the icon changes to a green check mark for 2 seconds.
- If the clipboard write fails, an error toast says so, for example "Failed to copy UUID to clipboard."
- Their state lives in `useConversationCopyAndExports` (`copiedUuid`, `copiedPath`) and reaches the header as props.

## What Changes

Every value in the table gets a copy button that works like the two that exist. A control works the same for every item in its scope (global rule "UI Controls: No Exceptions").

- **Session name:** a small copy button directly after the title, before the pin button. It shows only the icon, because the title is already there.
  - The title text itself stays plain text that you can select. A click on a heading that copies would surprise the user.
  - Its tooltip is "Click to copy session name", and its accessible name is "Copy session name".
- **Project path, git branch, and sandbox path:** the value becomes a copy button with the same look as the UUID button.
  - The folder icon, the branch icon, and the "Sandbox path:" label stay in front of the value, because they say what the value is.
  - The tooltips are "Click to copy project path", "Click to copy git branch", and "Click to copy sandbox path".
- **What a button copies:** the exact value from the API, with nothing added or removed. A long path that the header truncates is still copied in full. A Windows path is copied as the API returns it.
- **The two existing buttons keep their look and their tooltips** ("Click to copy UUID", "Click to copy file path"), because the e2e tests find them by those tooltips.

## Design

**One shared component, `CopyValueButton`** (decision D3), in `frontend/src/components/conversation/CopyValueButton.tsx`:
- **Props:**
  - `value`: the text to copy;
  - `label`: for example "project path", used in the tooltip, the accessible name, and the error toast;
  - `iconOnly`: for the title button;
  - `children`: the displayed value.
- **It owns its own "copied" state.**
  - It uses `useUnmountSafeTimer` for the 2-second reset.
  - A failed write shows `errorToast("Failed to copy <label> to clipboard.")`.
- **The UUID and file-path buttons move to it.** That removes `copiedUuid`, `copiedPath`, `onCopyUuid`, and `onCopyPath` from the hook, from the header's props, and from `ConversationPage`.
  - Six copy buttons with a flag each in the hook would mean six states and six timers in a page-level hook, for state that belongs to each button.
- **It does not read a context,** so it adds no re-render path (CLAUDE.md, "Performance Work", rule 1).

**An unnamed session gets no title copy button** (decision D1). The title then shows "Untitled", which is not the session's name. This follows the file-path button, which shows only when there is a file path.

**The git branch gets a copy button** (decision D2). It sits in the same row as the project path, and you often need it for `git checkout`.

## Event Orders to Check

The page component stays mounted when you open another conversation: the routes in `App.tsx` have no `key`, so React reuses `ConversationPage` and keeps its state. The copy feedback must belong to the value that was copied.

1. **Copy, then open another conversation within 2 seconds.** Today the check mark stays on the new conversation's UUID, because `copiedUuid` survives the change. After: a change of `value` clears the check mark at once.
2. **The clipboard write resolves after you open another conversation.** The button must not show the check mark for the new value. It shows the check mark only if `value` is the same as when the write started.
3. **Two clicks on one button within 2 seconds.** The check mark stays until 2 seconds after the last click. `useUnmountSafeTimer` already cancels the earlier timer.
4. **Clicks on two different buttons within 2 seconds.** Each button shows its own check mark, and one does not clear the other.
5. **The write fails** (for example, the page has no focus). An error toast shows, and no check mark.

These are catalog classes RC-UI-STALE-RESPONSE and RC-LIFECYCLE in race-condition-checker.

## Test Cases (for the tester; black-box)

**Unit tests (Vitest):**
1. Each copy button shows exactly when its value exists, for each source: Claude Code (name, UUID, file path, project path, branch), Cowork (name, UUID, sandbox path), and Desktop (name, UUID, file path when present).
2. A click writes the exact value, a truncated long path included. The check mark shows, and it changes back to the copy icon after 2 seconds (fake timers).
3. A rejected write shows the error toast with the right label, and no check mark.
4. A change of `value` clears the check mark.
5. A write that resolves after `value` changes does not show the check mark. Use a promise that the test holds and then resolves.
6. An unnamed session shows "Untitled" and has no title copy button.

**E2E tests (Playwright):**
1. For a Claude Code fixture with a project path and a branch, click each button in turn. Wait for the green check mark, then read the clipboard and compare it with the exact value. Do the same for a Cowork fixture and a Desktop fixture.
2. Copy the UUID of conversation A, then open conversation B from the Conversation List within 2 seconds. B's UUID button shows the copy icon, not the check mark.
3. `header-layout.spec.ts`: at 1280, 1366, and 1440 pixels, the action buttons do not cover the new buttons either.
4. No console errors or warnings in any of these tests.

**Each test must be able to fail:** remove the button, or the reset when the value changes, and confirm that the test fails.

## Decisions (the maintainer, 2026-10-28)

- **D1:** an unnamed session gets no title copy button, because "Untitled" is not its name.
- **D2:** the git branch gets a copy button too.
- **D3:** one shared `CopyValueButton` for all six values, and the UUID and file-path buttons move to it. This also fixes order 1 above for the buttons that exist today.
