## What CI does now

Workflow: `.github/workflows/windows-install.yml`. Trigger: a push to
`ci/windows-install`, or manual dispatch. Runners:

- `windows-latest` for x86_64 (Intel and AMD).
- `windows-11-arm` for ARM64 (Copilot+, Surface Pro X, Snapdragon X).

Both are free for public repositories.

**Job `install`** runs the README commands themselves, so the documentation
is under test and not merely the code:

- Install through the documented command, including the ARM x86_64-Python
  pin. The step prints the interpreter, which must report `AMD64` on an
  `ARM64` machine. That proves the Prism path.
- All five subcommands appear in `--help`.
- The Chromium build installs, and the executable resolves on disk.
- `serve` answers `/api/config` with HTTP 200.
- The watcher installs, `schtasks` finds it, the uninstall removes it, and a
  second query confirms it is gone.

**Job `pytest`** runs the Python suite on Windows. It runs serially with
`-n 0`. Parallel execution hid order-dependent failures, and the xdist
controller hung at shutdown on Windows.

## Why Playwright cannot cover the rest

Playwright drives a browser. The remaining tasks are not browser work.

- **C3-W** is a native Claude Desktop dialog. Playwright cannot reach
  another application's window chrome.
- **C6-W** needs Claude Desktop started with proxy flags, and a certificate
  authority trusted at the operating-system level. That is a trust decision
  in Windows, not an interaction with a page.
- **Real credential capture** is interactive by design. Automating a login
  through a proxy is the flow the security design intends to make hard.

The browser-shaped part is already automated: CI starts `serve` and asserts
a real HTTP 200.

## Manual walkthrough

Host: UTM 4.7.5 on Apple Silicon. VM: `claude-explorer-windows` (ARM64,
QEMU, 8 GB RAM). Maintainer notes: `~/.claude-explorer/vm-fleet.md`.

### Step 0. Free disk space first

A 37 GB image needs room for its write overlay. Boot with too little space
and a `qcow2` image can be corrupted. Check before you start.

### Step 1. Boot and upgrade

1. Open UTM. Double-click `claude-explorer-windows`.
2. In PowerShell, run `claude-explorer --version`.
3. Upgrade to the current main: `uv tool install --force claude-explorer`.

The VM carries the June build, which predates every fix in this document.

### Step 2. C5-W, the web UI in Edge

1. Run `claude-explorer serve`.
2. Open `http://localhost:8765` in Edge.
3. Confirm the conversation list renders.
4. Open one conversation. Confirm the messages render.
5. Run a search. Confirm results appear.
6. Confirm the source filter shows All, Desktop, Code, and Cowork.

**Pass:** all six render with no console error.

### Step 3. C3-W, the MCPB bundle

1. Download the `.mcpb` from the latest GitHub Release.
2. **Record the exact SmartScreen text**, and which path you had to take.
   That text belongs in the results document.
3. Drag the file into Claude Desktop, then Settings, then Extensions.
4. Confirm the install dialog appears, and accept it.
5. Confirm the five tools appear.

**Pass:** the five tools are listed and one returns data.

### Step 4. C4-W, PDF export

1. Install the GTK3 runtime. Follow the WeasyPrint Windows instructions.
2. Export any conversation as PDF from the web UI.

**Pass:** the file opens and carries the `%PDF` magic bytes.

**Skip this step** if the user only needs Markdown export. Markdown needs
no extra libraries, and the server starts normally without GTK.

### Step 5. C6-W, capture and fetch

This step carries the most risk. Do it last.

1. Start the proxy: `claude-explorer capture --proxy`.
2. Stop. The certificate file appears only after the proxy has run once.
3. Import the mitmproxy certificate authority into the current user's
   trust store. The CLI prints the command. Do this **before** you launch
   Claude Desktop, because `--ignore-certificate-errors` covers only
   Chromium's own requests and not the Electron main process.
4. Confirm your own install path with
   `Get-Process Claude | Select-Object Path`.
5. Launch Claude Desktop through the proxy. The CLI prints the command for
   your platform.
6. Click around in Claude Desktop for a minute.

**Pass:** the addon reports that it captured the credentials.

**If nothing is captured:** the Store-packaged build is ignoring the flags.
That is the outcome the June run predicted. Record it, then use the browser
capture instead, which needs no proxy.

## Known risks

- **Windows ARM cannot use `--proxy` at all.** mitmproxy publishes no
  Windows ARM64 wheels. The CLI says so and points at browser capture.
- **A Microsoft Store install of Claude Desktop may ignore the proxy
  flags.** See `2026.06.12-V2-cookie-storage-read.md`.
- **Credential files rely on an NTFS access control list on Windows**, not
  on mode bits. `harden_path_permissions` sets it. Verify with `icacls` if
  a user reports a permission problem.

## Open follow-ups

Found by council review on 2026-09-22 and verified against the code. None
is fixed yet.

- **`os.replace` on Windows.** Four writers use the temp-file-then-replace
  pattern: `preferences.py`, `credentials.py`, `bulk_fetch.py`, and
  `migrate_to_v2.py`. On Windows this raises `PermissionError` when
  antivirus or another reader holds the destination open. Needs a bounded
  retry.
- **SQLite WAL side files.** The `-wal` and `-shm` handles are the same
  family as the read-connection leak already fixed in `SearchIndex.close()`.
  Audit any other module that opens a database.
- **Wall-clock versus monotonic time.** Timeout and retry logic that uses
  `time.time()` misbehaves when the clock moves. Prefer
  `time.monotonic()`.
- **Test-suite order dependence.** Several tests pass under xdist sharding
  and fail serially. Two were fixed; the class is not exhausted. Run the
  suite with `-n 0` periodically to surface more.
