# Sidebar list filters: project, path, and recent sessions (2026-10-25)

## Why

- **Too many old sessions.** The Conversation List shows every session, also the ones that ended weeks ago. The user wants to see only the sessions that are active now.
- **No project filter in the list.** The Search Pane can scope search to a project (the scope pin), but the Conversation List cannot show only one project.
- **Folder order is wrong.** With "Group sessions by project" on, the folders do not follow the sort that the user selects.
- **The grouping checkbox can hide while grouping stays on.** Under the "Claude Desktop" or "Claude Cowork" source, the checkbox is hidden, but the list still groups.

## Decisions (the user, 2026-10-25)

- The conversation-header control is a **separate list filter**. The search scope pin keeps its meaning (it dims rows; UX.md §5).
- The recent-sessions control is in the sidebar: a checkbox and a number field, `[x] Last [24] h`, on its own row below the sort controls.
- **No exceptions.** A filter applies to every row. The open conversation is hidden when a filter excludes it.
- **Folder order:** a folder takes the value of its first session in the chosen order. For a descending sort, that is the largest value in the folder. For an ascending sort, it is the smallest. This applies to every sort field.

## Behavior (the contract)

### Recent sessions

- A checkbox and a number field on its own sidebar row, below the sort controls: `[x] Last [N] h`.
- **Default:** on, N = 24.
- When on, the list hides each row whose `updated_at` is older than now minus N hours.
- "Now" is the browser clock. The list applies the cutoff again at least once a minute, so a row that becomes too old leaves the list without a reload.
- N is a whole number, 1 or more. The field is a text field (`inputmode="numeric"`), so it accepts any typing, but it saves only a whole number of 1 or more. It does not save an empty field, 0, a negative number, or text. On blur, the field shows the saved value again.
- The number field is disabled while the checkbox is off.
- Per-user preferences: `listRecentOnly` (boolean) and `listRecentHours` (number), saved like `showPhantomSessions`.

### Project and path filter

- **Project** (`?project=<name>`): shows only the rows whose `project_name` equals `<name>`, ignoring case. `project_name` is the last folder of `project_path`, so one project can hold several paths.
- **Path** (`?path=<path>`): shows only the rows whose `project_path` equals `<path>` exactly.
- Only one of the two is active. Setting one removes the other from the URL. Other URL parameters (`pin`, `q`, `title`) stay.
- Rows without a project (Claude Desktop, Cowork) do not match a project or path filter.
- The filter is per tab, in the URL, like the scope pin. A reload keeps it.

### Sidebar project control

- A select in the sidebar, always shown, below the source and workspace selects.
- **Options:** "All projects", then each `project_name` of the loaded list, sorted by name, ignoring case. The options come from the list before the project, path, and recent filters, so they do not change when those filters change.
- Selecting a project sets `?project=` and removes `?path=`. "All projects" removes both.
- While `?path=` is active, the select shows one more option, "Path: <path>", and it is selected.

### Conversation-header control ("List" menu)

- A button next to "Search scope", shown only for a Claude Code session with a `project_path`.
- **Label:** one of four:
  - "List: all" when no project or path filter is active.
  - "List: project" when the active filter is this conversation's project.
  - "List: path" when the active filter is this conversation's path.
  - "List: other" when a filter for another project or path is active.
- **Menu items:**
  1. "Show only this project": sets `?project=<project_name of this conversation>`.
  2. "Show only this path": sets `?path=<project_path of this conversation>`.
  3. "Show all projects": removes both. Disabled when no project or path filter is active.

### Filters together

- Every list filter combines with AND: source, workspace, title search, active named filter, URL title filter, project or path, recent, empty sessions, archived sessions.
- **Empty state:** when the loaded list has rows but the filters hide all of them, the list says so and names each active filter, for example "All 12 conversations hidden by project=foo and last 24 h." It gives one button for each filter that it can clear:
  - "Clear active filter" (existing).
  - "Show all projects" when a project or path filter is active.
  - "Show older sessions" when the recent filter is on. It turns the checkbox off.

### Grouping ("Group sessions by project")

- The list groups only when the checkbox is shown and checked. The checkbox shows for the sources "All Conversations" and "Claude Code". Under "Claude Desktop" or "Claude Cowork", the list is flat, also when the saved setting is on.
- Grouping uses the filtered rows. A folder with no visible rows is not shown. A folder's count is its number of visible rows.
- **Folder order:** see "Decisions". The value of a session for each sort field:
  - Last Activity: `updated_at`.
  - Start Time: `created_at`.
  - Title: `name`, ignoring case.
  - Project: the folder name, ignoring case.
  - A tie sorts by folder name, A to Z.
- Inside a folder: starred rows first, then the others, each in the chosen order (no change).
- **Keyboard order:** `j`/`k` and the arrow keys move through the rows in display order: folder by folder, top to bottom. They skip the rows of a collapsed folder.

## Test harness

- The e2e fixtures seed `listRecentOnly: false` by default, because fixture dates are fixed in the past. A test of the recent filter turns it on, and sets the browser clock with `page.clock`.

## Test cases (black-box; for the tester)

1. **Recent, default on:** sessions at now−1 h, now−23 h, now−25 h, now−10 days; with no saved preference, only the first two show. Turn the checkbox off: all four show, and a preference PATCH sends `listRecentOnly: false`.
2. **Recent, N:** set N to 48: the 25-hour session shows. Type 0, then blur: the field shows 48 again, and no PATCH sends 0. The same for an empty field and for text.
3. **Recent, the clock moves:** with N = 24, a session at now−23 h shows. Run the clock 2 hours forward without a reload: the session leaves the list.
4. **Recent, field disabled** while the checkbox is off.
5. **Project select:** options are "All projects" and the project names, sorted. Pick one: the URL has `?project=`, and only that project's rows show. "All projects": all rows show, and the URL has no `project` or `path`.
6. **Header, path vs project:** sessions in `/a/foo`, `/b/foo`, and `/c/bar`. From a `/b/foo` session, "Show only this path" shows only the `/b/foo` rows, and the label is "List: path". "Show only this project" shows the `/a/foo` and `/b/foo` rows, and the label is "List: project". "Show all projects" shows all rows.
7. **Header, hidden** for a Claude Desktop conversation and for a Cowork session.
8. **Header, keeps other URL parameters** (`pin`, `q`).
9. **No exceptions:** with the recent filter on, open a 10-day-old session by URL. The conversation pane shows it, and the list does not have its row.
10. **Empty state:** a project filter and the recent filter hide all rows. The message names both filters. "Show older sessions" turns the checkbox off. "Show all projects" removes the URL filter.
11. **Folder order:** for each sort field and each direction (8 cases), folders follow the rule in "Grouping". Use fixtures where the folder-name order and the first-session order differ.
12. **Grouping off under Desktop and Cowork:** with the saved setting on, the source "Claude Desktop" gives a flat list with no folder headers. The same for "Claude Cowork".
13. **Grouping with filters:** a folder whose rows are all older than N is not shown. A folder's count equals its visible rows.
14. **Keyboard order, grouped:** `j` moves through the rows in display order. Collapse a folder: `j` skips its rows.
15. **Reload keeps state:** the project or path filter (URL) and the recent setting (preference) survive a reload.
16. **No console errors or warnings** in any of these tests (TESTING.md §5.15).
