# Sidebar list filters, round 4: one collapsible section, and "Forever" by default (2026-10-26)

This revises the three earlier specs ([round 1](./2026.10.25-sidebar-list-filters.md), [round 2](./2026.10.26-list-filter-dropdowns.md), [round 3](./2026.10.26-list-project-key.md)). Every rule there stays unless this file replaces it.

## Why

- Eight controls now sit above the Conversation List, so the list starts far down the sidebar, and on a short screen the controls take most of its height.
- The recent-sessions filter hides old sessions by default, which surprises a user who opens the app to find an old conversation.

## Decisions (the user, 2026-10-26)

- The controls go into one collapsible section, **Filters and Sorting**, closed by default. The app remembers whether it is open, also across restarts.
- The time dropdown's default is **Forever** (the filter off).

## Behavior (the contract)

### Default window

- With no saved choice, the time dropdown shows "Last: Forever", and the list shows every session.
- A saved choice does not change: a user who picked "8 hours" keeps "8 hours".
- In preference terms, `listRecentOnly` defaults to `false`. `listRecentHours` keeps its default of 24, so that a later pick of the dropdown's "1 day" means what it says.

### The "Filters and Sorting" section

- **Inside the section**, in this order: the active-filter picker, the source select, the workspace select (when shown), the project picker, the sort field and direction, the time dropdown, and the row with "Group sessions by project", "Empty", "Archived", and the **`⌘K`** hint.
- **Above the section**, always visible: the sidebar header (title and Refresh) and the "Search titles and projects" field.
- **The header** of the section is a button with the text "Filters and Sorting" and a chevron. A click opens or closes the section.
- **Default:** closed.
- **Saved state:** per-user preference `sidebarFiltersOpen` (boolean), saved like the other sidebar preferences, so a reload and a server restart keep it.
- **Count of active filters:** the header shows "N active" when N is 1 or more, open or closed. A filter counts as active when it differs from its default:
  - the active-filter picker is not "All conversations";
  - the source is not "All Conversations";
  - a workspace is selected;
  - a project or path filter is on;
  - the time dropdown is not "Forever";
  - "Empty" is checked;
  - "Archived" is checked.
  - The sort, its direction, and "Group sessions by project" do not count: they order the list; they do not hide rows.
- The empty-state message of the list (round 1) does not change; it names each active filter, also while the section is closed.

## DOM hooks

| Element | Hook |
|---|---|
| Section header button | `data-testid="sidebar-filters-toggle"`, `aria-expanded="true\|false"` |
| Section content | `data-testid="sidebar-filters"` (not in the page while closed) |
| Count of active filters | `data-testid="sidebar-filters-active-count"`, text "N active" (not in the page when N is 0) |

## Test harness

- The e2e fixtures seed `sidebarFiltersOpen: true` by default (beside `listRecentOnly: false`), so that the existing tests find the controls. A test of the section's default closes or omits it on purpose.

## Test cases (black-box; for the tester)

39. **Default closed:** with no saved `sidebarFiltersOpen`, the section is closed: the source select, the project picker, the sort, and the time dropdown are not in the page, and the search field is visible.
40. **Open and close:** a click on the header opens the section and shows every control; a second click closes it. `aria-expanded` follows.
41. **Kept across a reload:** open the section; a PATCH sends `sidebarFiltersOpen: true`; after a reload it is still open. Close it, reload: it is closed.
42. **Count:** with the default settings, no count shows. Turn on, one at a time, each filter in the list above: the count goes up by one each time ("1 active", "2 active", …). Changing the sort, its direction, or the grouping changes no count. The count shows also while the section is closed.
43. **Forever by default:** with no saved `listRecentOnly`, the dropdown shows "Last: Forever", and a session from two years ago is in the list.
44. **A saved window stays:** with `listRecentOnly: true` and `listRecentHours: 8` saved, the dropdown shows "Last: 8 hours", and a 9-hour-old session is not in the list.
45. **The list gains height:** in a 1280×720 window with the section closed, the list area is taller than with the section open.
46. **No console errors or warnings** in any of these tests.

Round 1 case 1 ("Recent, default on") and round 2 case 18 ("the default is 1 day") change: the default is now "Forever". Keep what else they check.
