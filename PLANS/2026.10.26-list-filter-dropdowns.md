# Sidebar list filters, round 2: a time dropdown and a project picker you can type in (2026-10-26)

This revises [2026.10.25-sidebar-list-filters.md](./2026.10.25-sidebar-list-filters.md). Every rule there stays unless this file replaces it.

## Why

- The `[x] Last [N] h` row asks the user to type a number of hours. Common windows such as "1 week" or "3 months" need arithmetic, and "all sessions" needs a separate checkbox.
- The project select lists projects A to Z. A user with 70 projects wants the projects that they work in now at the top, and a way to find one by typing part of its name.

## Decisions (the user, 2026-10-26)

- The recent control becomes one dropdown with common windows, and "Forever" turns the filter off.
- The project list sorts by time, newest first, and the user can type to filter it.
- "7 days" and "1 week" are the same window, so the dropdown shows only "1 week".

## Behavior (the contract)

### Time dropdown (replaces the checkbox and the hours field)

- A dropdown on the same sidebar row as before, below the sort controls. Its trigger shows "Last: <option>", for example "Last: 1 day".
- **Options, in this order, with the hours that each one means:**

  | Option | Hours |
  |---|---|
  | 8 hours | 8 |
  | 1 day | 24 |
  | 3 days | 72 |
  | 1 week | 168 |
  | 2 weeks | 336 |
  | 1 month | 720 (30 days) |
  | 3 months | 2160 (90 days) |
  | 6 months | 4320 (180 days) |
  | 1 year | 8760 (365 days) |
  | Forever | no limit |

- **Default:** 1 day.
- **Preferences:** the same keys as before, so saved settings and the e2e fixtures keep working.
  - "Forever" saves `listRecentOnly: false`.
  - Every other option saves `listRecentOnly: true` and `listRecentHours: <hours>`.
- **A saved number of hours that is not in the table** (from the old hours field, for example 48): the dropdown shows one more option, "48 hours", in its place by size, and it is selected. When the user picks another option, that extra option goes away.
- Every other rule of the recent filter stays: the cutoff moves once a minute, and the empty state names the window ("last 1 day", "last 2 weeks") and gives "Show older sessions", which sets "Forever".

### Project picker (replaces the project select)

- A button in the same place as the project select. Its label is the current choice: "All projects", the project name, or "Path: <path>".
- A click on the button opens a panel with a text field ("Type to filter projects"), which has the focus, and a list below it.
- **List order:**
  1. "All projects", always first, also while the user types.
  2. "Path: <path>", only while a path filter is active.
  3. The projects, newest first: each project sorts by the latest `updated_at` of its loaded sessions. A tie sorts by name, A to Z, ignoring case.
- **Which projects:** each `project_name` of the loaded list, before the project, path, and recent filters (no change from round 1).
- **Typing** keeps only the projects whose name contains the typed text, ignoring case. The order stays newest first. If no project matches, the list says "No matching project".
- **Keyboard:** the arrow keys move the highlight; Enter picks the highlighted entry; Escape closes the panel and keeps the current choice. A click on an entry picks it.
- Picking a project sets `?project=` and removes `?path=`. "All projects" removes both. Picking closes the panel and clears the typed text.

## DOM hooks

| Element | Hook |
|---|---|
| Time dropdown trigger | `data-testid="sidebar-recent-select"` |
| Time options | the dropdown's options, by their text in the table above |
| Project picker button | `data-testid="sidebar-project-select"` (the same id as round 1) |
| Project filter field | `data-testid="sidebar-project-filter"` |
| Project list entries | `role="option"`, with the entry text as the name |

The hooks `sidebar-recent-toggle` and `sidebar-recent-hours` go away.
