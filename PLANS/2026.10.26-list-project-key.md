# Sidebar list filters, round 3: what a "project" is, and labels with context (2026-10-26)

This revises [2026.10.26-list-filter-dropdowns.md](./2026.10.26-list-filter-dropdowns.md) and [2026.10.25-sidebar-list-filters.md](./2026.10.25-sidebar-list-filters.md). Every rule there stays unless this file replaces it.

## Why

- The project picker shows only the last folder of a path, so a session in `~/Source/clientco/ai` shows as "ai". On the user's data, 72 folders have only 68 names, so 4 names each join two or more unrelated folders, and 4 names are generic (such as "ai").
- The header button "List: all" does not say what it does, and the user did not find it.

## Decisions (the user, 2026-10-26, after a consult with GPT-6 Astra)

- A per-user setting chooses what a project is. **Folder path** is the default; **Folder name** keeps the round-1 behavior, which joins folders with the same last name.
- In path mode, an entry's label is the last two folders, with more folders when two labels would be the same, and the full path is the second line.
- Paths show relative to the home folder (`~/Source/clientco/ai`). The backend reports the home folder.
- The header button says "Filter list" when no project filter is on.
- A repo-root key is out of scope: the backend does not know a session's repo root, and old sessions can point at folders that no longer exist.

## Behavior (the contract)

### The setting

- **Settings → Conversation List → "Projects are"**, two options:
  - **Folder path** (default): "Each folder is its own project."
  - **Folder name**: "Folders with the same name are one project."
- Per-user preference `listProjectKey`: `"path"` or `"name"`. A missing or unknown value means `"path"`.

### Home folder

- `GET /api/config` returns `home_dir`, the absolute home folder of the user that runs the server.
- **Display path:** a path inside the home folder shows as `~/` plus the rest (`~/Source/clientco/ai`); the home folder itself shows as `~`. Any other path shows as it is.
- The page splits a path on `/` and on `\`, so that Windows paths work too.

### Inventory

The picker and the folders work from the **inventory**: the Claude Code sessions of the loaded list, before the project, path, and recent filters (as in rounds 1 and 2).

### Path mode (`listProjectKey: "path"`)

- **One entry per distinct `project_path`.**
- **Label:** the last 2 parts of the display path, joined with `/`. If two or more entries of the inventory have the same label, each of them grows by one more part, and so on, until every label is unique or an entry has no more parts. A display path with 2 parts or fewer is its own label.
  - Example: `~/Source/clientco/ai`, `~/Work/clientco/ai`, and `~/Source/other/ai` give "Source/clientco/ai", "Work/clientco/ai", and "other/ai".
  - Example: `~/foo` gives "~/foo".
- **Second line:** the display path, always visible in the picker.
- **Order:** newest first, by the latest `updated_at` of the entry's sessions; a tie sorts by label, A to Z, ignoring case.
- **Typing** keeps the entries whose label or display path contains the text, ignoring case.
- **Picking** an entry sets `?path=<project_path>` (the absolute path) and removes `?project=`.
- **Folders** ("Group sessions by project"): one folder per `project_path`. The folder header shows the entry's label, and its tooltip shows the display path. A Claude Code session without a path goes in "Unknown Project". The folders of other sources do not change.
- **An old `?project=<name>` link** still filters by name. The picker button shows "<name> (all folders)", and the list shows that entry as the selected second entry. "All projects" clears it.

### Name mode (`listProjectKey: "name"`)

- The round-1 and round-2 behavior: one entry per `project_name`, picking sets `?project=`, and folders group by name.
- **Label:** the name. **Second line:** the display path when the name has one folder; else "N folders", and the tooltip lists the display paths.
- **Typing** keeps the entries whose name or display paths contain the text.

### Header button (replaces the "List: …" labels)

| Mode | Active filter | Label | `data-list-filter` |
|---|---|---|---|
| any | none | Filter list | `all` |
| path | `?path=` this conversation's path | List: this project | `path` |
| name | `?project=` this conversation's name | List: this project | `project` |
| name | `?path=` this conversation's path | List: this folder | `path` |
| any | any other project or path filter | List: other project | `other` |

- **Menu items:**
  - Path mode: "Show only this project" (sets `?path=`), then "Show all projects".
  - Name mode: "Show only this project" (sets `?project=`), "Show only this folder" (sets `?path=`), then "Show all projects".
- "Show all projects" is disabled when no project or path filter is on (no change).
- Hooks: `list-filter-project` is "Show only this project" in both modes (in path mode it sets `?path=`); `list-filter-path` is "Show only this folder" (name mode only); `list-filter-clear` is "Show all projects".

## DOM hooks

| Element | Hook |
|---|---|
| The setting's options | `data-testid="settings-project-key-path"`, `data-testid="settings-project-key-name"` |
| A picker entry's second line | `data-testid="project-entry-detail"`, inside the entry (`role="option"`) |
| A folder header | `data-testid="list-group-header"`, `data-group-name="<label>"`, `title="<display path>"` |

The rest is as in rounds 1 and 2.
